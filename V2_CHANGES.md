# V2 CHANGES: Station Deutsch

Change spec for the existing build. Read it together with `PRD.md`, `LEARNING_DESIGN.md`, `DESIGN.md` and `TECH.md`. Where this file and an older doc disagree, **this file wins**, and you must update the older doc in the same commit.

## How to work

1. Work phase by phase, in order. Commit after each phase with a clear message and report what works and what does not.
2. In every phase: write the failing test first, then fix.
3. Do not start Phase 3 until Phases 0 to 2 are done and `npm run test` and `npm run build` pass.
4. Do not invent German content. Do not mark any content as verified.
5. Keep quota in mind: batch related edits, avoid repeated tiny changes.
6. At the end of each phase, list any item you skipped and why.

## Phase 0: Honesty and content hygiene

The current build claims things that were not actually done. Fix this before anything else.

**0.1 Verification status.** Set `verification.status` to `unverified` and clear `sources` for every entry in `content/words.json` and `content/placement.json`, unless the entry already has a specific, checkable source (a page or URL for that exact word). Generic text such as "Goethe A1 Wortliste" is not a source. The strict validator must now fail until a human verifies entries. Production build keeps the non-strict check.

**0.2 README.** Remove the "5-tester feedback log" and any other claim that testing or verification happened. Replace with:
- A "Content status" section with counts generated by the validator: total, verified, unverified, per topic and level.
- A "Test log" section with an empty template (date, tester type, task, what broke, what changed). The owner fills it with real tests.
- A "Why no login yet" section: the brief does not ask for accounts, sign-up friction would hurt a prototype review, and the next step would be optional sign-in to sync progress across devices.
- "What I would build next".

**0.3 Parked words.** Move these entries from `content/words.json` into `content/words.parked.json` (not loaded by the app), and print a report listing them: Schüttelfrost, Atemnot, Allergiereaktion, Entzündung, Katheter, Verbandwechsel, Dokumentation, Rehabilitation, Wirbelsäule, bettlägerig. Reason: likely above beginner level. The owner will approve or restore each one. After moving them, confirm every topic and part of speech still has at least 4 entries for distractors. If not, say which and stop.

**0.4 Spelling.** The care entry for "bettlaegerig" uses an ASCII spelling. If it stays in the bank after the owner's review, its `de` field must be "bettlägerig". Add a validator rule that flags headwords containing "ae", "oe" or "ue" where an umlaut is likely, as a warning.

**0.5 Verification worksheet.** Add `npm run content:worksheet`, which writes `content/verification-worksheet.md`: one table row per word with columns id, article, headword, plural, English, level, example sentence, a Wiktionary link (`https://de.wiktionary.org/wiki/<headword>`), a Duden search link, and empty columns for "article ok", "plural ok", "on Goethe list (A1/A2/none)", "sentence ok", "checked by", "source". The owner fills this in by hand.

**0.6 Counts.** The validator prints exact counts. Do not hard-code counts anywhere in docs or the README.

**0.7 Distractor overlap.** A distractor must never overlap in meaning with the correct answer. Implement both: (a) automatic: reject a distractor if its English text shares a content word with the target's English (for example "back pain" next to "pain"); (b) optional `conflicts: string[]` on a word (ids that must never appear together as options), checked by the validator. Add unit tests.

## Phase 1: Bug fixes

**1.1 Match-pairs freeze (highest priority).** After a match exercise completes, the next exercise never loads.
- Reproduce first and report the console errors.
- Write a failing test: complete a match item and assert the session advances. Add a Playwright version.
- Check and report which of these is true: no completion callback or no way to advance; the match component keeps state between items because the session item has no unique `key`; `recordAttempt` or the grader throws on a multi-word item; pairs keyed by display text so duplicate English glosses break completion; a render loop.
- Spec: a match item counts as **one** session item. It logs one `Attempt` per word. A word is correct on first try only if no wrong partner was tapped for it. When all pairs are matched, show a short sheet ("4 of 4 matched, 1 slip") with a Continue button, then advance. Pair ids use word ids, not text.

**1.2 Error boundary.** Wrap each exercise in an error boundary. If one throws, log it, skip to the next item, and never freeze the session.

**1.3 Counter.** The session total stays fixed (for example 10). Retries do not change the denominator. Show a small "Retry" label on retried items. Fix "1/10" turning into "1/11".

**1.4 Demotion rules (change to `LEARNING_DESIGN.md` §2 and §3).** Update the doc and the code:

| Result | Box change |
|---|---|
| Correct first try | +1 (once-per-day cap) |
| Right word, wrong article | **-1**, minimum box 1, logged `article` |
| Spelling near-miss | no change, logged `spelling` |
| Wrong word or meaning | box 1, logged `meaning` |

A stubborn word cannot be promoted above box 2 until it clears. The weak words list on Home and Progress must never show a "Mastered" state: show "missed N times" instead. Add tests for every row, plus: a word missed twice in its last five attempts is never displayed as Mastered.

**1.5 Demo data.** Make `demo.ts` realistic and consistent with the rules: spread attempts over about 5 days; mix error types (for example article 6, meaning 4, spelling 3); no word with two or more recent misses in box 4 or 5; box counts must match the attempt history. Label it clearly as sample data.

**1.6 Buttons and layout.** Fix these visible bugs:
- The Flip pill is a thin vertical sliver. It must be full width of the content column, 56 px high.
- "Choose my level" and "Learn new words" text touches the pill edge. All pills: full column width, `padding: 0 24px`, `min-height: 56px`, `box-sizing: border-box`.
- "Check" must be the same width as the option pills.
- Add global CSS `button, input, select, textarea { font: inherit; }` so buttons use Figtree. Fix "Progress →" and "(change)" which render in a system font.
- Replace the arrow glyph with a Lucide chevron icon.
- The feedback sheet must align to the app container width, not the viewport.

**1.7 Answer marks.** After "Check" on multiple choice, mark the correct option with a tick and mint outline, mark a wrong chosen option with a cross and coral outline, and dim the rest. Never use colour alone.

**1.8 Progress screen.**
- "Practise these" must be visible on black (add an `on-black` button variant with a white outline).
- Hide error types that have no exercise in the build (plural stays hidden until a plural exercise exists).
- Labels in sentence case, not all caps.

**1.9 Tests.** Add tests for 1.1 to 1.4 first. Add a Playwright smoke test for the full journey: welcome, choose level, learn a batch, a match item, advance, a wrong answer with feedback, retry, summary, progress, simulate tomorrow.

## Phase 3: Value features

**Data model changes**
- `Attempt` gains `given: string | null` and `expected: string | null`.
- `AppState` gains `sessions: SessionSummary[]` (cap 30), where `SessionSummary = { id, at, accuracy, answered, promotedIds: string[] }`.
- `Word` gains optional `conflicts?: string[]` and optional `pronunciationTip?: string`.
- Bump persisted `version` to 2 and ignore older stored data.

**3.1 Next review and trend.** On the Summary:
- If words are due now: "N words are due now."
- Otherwise: "Next review: tomorrow, N words" (or "in X days"), using the app clock.
- If a previous session exists: "Last session 60%, today 80%."
Add unit tests that include the simulated clock.

**3.2 My mistakes** (`#/mistakes`). A list grouped by word, newest first: word with article chip, "You chose X", "Correct: Y", error type, how long ago, and a "Fixed" badge when the latest attempt on that word was correct. A "Practise these" button starts a session using only those words (`composeSession` accepts an optional `pool` of word ids). Linked from Home and Progress.

**3.3 Ward context.** Show the topic name as a small label on every learn card and exercise ("Care actions"). Prefer the entry's sentence whenever one exists. Do not write new German sentences.

**3.4 Topic map.** Replace the generic "Learn new words" flow with five topic cards on Home: "Body, 4 of 15 words". "Learned" means box 1 or higher at the chosen level. Tapping a card starts a learn batch (5 to 8 new words) from that topic. If no new words remain: "You've seen every Body word. Practise them", which starts a practice session on that topic.

**3.5 Share weak words.** A "Share my weak words" button opens `https://wa.me/?text=<encoded text>` with a short list of the learner's weak words. No phone number. It shares only what the learner chooses to send.

**3.6 Export and import progress.** In Settings: "Download my progress" (JSON file) and "Restore from file". Validate the file's version and shape before loading and show a clear error if it is invalid.

**3.7 Optional Skillcase link.** Add a constant `SKILLCASE_DEMO_URL` in the constants file. If it is empty (the default), show nothing. If set, show a quiet "Learn live with Skillcase" link on the Summary.
